## Перед началом работы

Перед внесением изменений рекомендуется:

1. Ознакомиться с архитектурой проекта.
2. Проверить актуальные задачи и обсуждения.
3. Убедиться, что изменение не ломает публичные API-контракты.
4. Для крупных изменений предварительно обсудить подход с мейнтейнерами.
5. Проверить, требуется ли обновление документации, OpenAPI-контракта или SDK.

## Ветки

Рекомендуемая схема веток:

- `main` — стабильная основная ветка;
- `develop` — ветка активной разработки, если используется;
- `feature/<name>` — новые возможности;
- `fix/<name>` — исправления;
- `security/<name>` — исправления безопасности;
- `docs/<name>` — изменения документации.

## Коммиты

Сообщения коммитов должны быть короткими и понятными.

Рекомендуемый формат:

```text
type(scope): краткое описание
```

Примеры:

```text
feat(api): добавить базовый contract для content types
fix(queue): исправить обработку повторных задач
docs(wiki): обновить раздел по расширениям
security(auth): усилить проверку api token scopes
```

Типы:

- `feat` — новая возможность;
- `fix` — исправление;
- `docs` — документация;
- `refactor` — рефакторинг без изменения поведения;
- `test` — тесты;
- `build` — сборка и зависимости;
- `ci` — CI/CD;
- `security` — исправления безопасности;
- `chore` — служебные изменения.

## Pull Request / Merge Request

Перед отправкой изменений:

1. Убедитесь, что код проходит локальные проверки.
2. Добавьте или обновите тесты, если изменение влияет на поведение.
3. Обновите документацию, если изменение влияет на API, CLI, конфигурацию, расширения или поведение системы.
4. Не смешивайте несвязанные изменения в одном запросе.
5. Укажите, какие подсистемы были изменены.

В описании запроса желательно указать:

- цель изменения;
- список основных правок;
- влияние на совместимость;
- инструкции по проверке;
- связанные задачи или обсуждения.

## Совместимость

CajeerEngine следует SemVer.

Изменения, которые могут нарушить обратную совместимость, должны быть явно описаны в `CHANGELOG.md`.

Особенно аккуратная политика совместимости требуется для:

- REST API;
- OpenAPI-контракта;
- extension API;
- manifest-формата расширений;
- CLI-команд;
- структуры конфигурации;
- миграций базы данных.

## Документация
