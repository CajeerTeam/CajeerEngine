## Задача продукта

Обычно публикации, API, перенос контента, аналитика, права доступа и безопасное обновление живут в разных сервисах. CajeerEngine объединяет эти задачи вокруг одного ядра: от модели контента и административных действий до миграций и восстановления.

Продукт предназначен для команд, которым важны контроль над собственным сервером, программный доступ к данным и возможность развивать CMS через интеграции и расширения. Это не SaaS и не готовый многосерверный кластер.

## Кому и для чего

| Роль | Типовой сценарий | Что получает |
| :-- | :-- | :-- |
| **Редактор** | Управлять страницами, материалами и медиа | Редакционный интерфейс, статусы публикации, ревизии |
| **Разработчик** | Создать витрину, приложение или интеграцию | REST API, OpenAPI, TypeScript SDK, шаблоны и расширения |
| **Администратор** | Обеспечить предсказуемые обновления и контроль доступа | Диагностика, роли, 2FA, очередь задач, журнал и резервное копирование |
| **Команда миграции** | Перенести существующий сайт | Импорт DLE/WordPress, план переноса, проверка, подтверждённое переключение |
| **Команда контента/аналитики** | Автоматизировать подготовку материалов и оценку результатов | Опциональные AI-инструменты, аналитика, SEO и интеграции |

## Четыре опоры системы

### Контент как управляемая модель

Типы контента, записи, ревизии, публикация, медиа, локализация, поисковая индексация и SEO-маршруты формируют единый контур работы с материалами. Публичный сайт может использовать встроенные шаблоны `.cjr`; внешние потребители работают через API.

### Открытость для разработки

В каталоге проекта есть OpenAPI-описание (`api/openapi.yaml`), пакет TypeScript SDK (`packages/ts-sdk`), CLI и Extension Platform. Изменения продукта можно развивать собственными расширениями и интеграциями — при соблюдении правил совместимости и прав доступа.

### Инструменты для сложных задач

Migration Center поддерживает процессы переноса DLE и WordPress; интеграции аналитики и AI-инструменты реализованы отдельными модулями. Наличие модуля в исходниках **не означает**, что внешние провайдеры будут доступны без настройки, ключей доступа и сетевого подключения.

### Управляемая эксплуатация

Система включает диагностику, очередь и планировщик, механизм выпуска подписанных архивов, обновления с подтверждением администратора, резервное копирование и восстановление. Для выпуска 2.1.0 критична отдельная служба обновлений с актуальным heartbeat.

## Границы и требования

| Направление | Что важно знать до выбора |
| :-- | :-- |
| **PHP** | `>=8.4.1 <9.0`, Composer 2 для работы из исходников |
| **База данных** | PostgreSQL 17+ — основной профиль; PostgreSQL 18+ рекомендован; SQLite — локальные сценарии; MySQL/MariaDB — дополнительные драйверы |
| **Развёртывание** | Описанный и проверяемый производственный профиль — один Linux-узел с Nginx, PHP-FPM и systemd |
| **Админка** | Production Static SPA находится в `public/admin`; Nuxt используется также в исходниках для разработки |
| **Обновления** | Автоматическое обнаружение выпуска не означает автоматическую установку: требуется согласование администратором |
| **AI/SSO/аналитика** | Опциональные внешние сервисы, требующие настроек, сетевого доступа и отдельной приёмки |
| **Гарантии** | Из наличия тестов или номера версии не следует универсальная сертификация под любую инфраструктуру |
