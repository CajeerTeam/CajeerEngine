# CajeerEngine 1.6.5 — AI CMS Diagnostics

## Что реализовано

Администратор с правом `system:read` открывает раздел **AI CMS Diagnostics** в Nuxt (`/admin/diagnostics`) или в production static SPA (`/admin/#/diagnostics`). Панель выполняет реальные health/readiness-пробы `OperationsMonitor`, проверку настроек `SecurityHardener` и ограниченную агрегацию событий существующего JSONL-журнала (15 минут — 24 часа). Результат содержит факты, проверяемые причины и **предлагаемые, но не исполняемые** действия.

- БД и схема/миграции, права записи в storage, backend очереди, количество failed jobs и возраст backlog.
- Свежесть задач scheduler, heartbeat worker, резервного копирования, сбои обновлений, доступность cache/search и опциональных traces.
- Security hardening: защита API, контента и системных маршрутов, debug, минимальная длина пароля, ключи интеграций и OIDC.
- Кумулятивные HTTP-метрики, количество 5xx; ограниченные по времени агрегаты **только фиксированных безопасных событий** runtime-журнала.
- Детерминированные правила тяжести, понятное объяснение и команды для ручной проверки.
- Отдельное объяснение через настроенный OpenAI Responses API, с выбором конкретной проблемы или всех проблем, экспорт JSON отчёта.

**Важно:** показатели HTTP-метрик накопительные, а не обязательно ограничены выбранным периодом журнала. Никакого изменения БД, запуска произвольных команд, перезапуска сервисов, автоматического исправления конфигурации или доставки исходных логов в OpenAI не производится. Провайдеру передаются только явно разрешённые поля и типизированные агрегаты, коды проверок и инструкции по проверке; SQL, токены, IP, URL, текст исключений, произвольный контекст не отправляются.

## Безопасность и доступ

- `GET /api/v1/ai/diagnostics?window_minutes=60`: требуется браузерная административная сессия и `system:read`.
- `POST /api/v1/ai/diagnostics/explain`: те же права плюс CSRF, body `{ "window_minutes": 60, "focus": "queue_failed" }`. `focus` допускает только существующие коды замечаний. Rate limit — 3 объяснения в минуту на пользователя.
- OpenAI-ключ остаётся на сервере. Используются `AiSettings`, `OpenAiClient` и единый месячный бюджет `ce_ai_usage`, конкуренция генераций ограничена lease `ce_ai_editor_jobs`. Неуспешные обращения освобождают резерв токенов.
- Запрещённые и неизвестные поля отбрасываются в сервисе **до** вызова модели. Ответ модели отображается как текст, без HTML-интерпретации.
- Аудит `ai.diagnostics.explained` записывает только ID пользователя, код проблемы и число обнаруженных проблем, не содержимое логов.

## Установка

1. Сделайте backup БД и файлов, а затем наложите *changed-only* ZIP поверх **полной 1.6.4**.
2. Перезапустите PHP-FPM и сбросьте OPcache. Убедитесь, что сервер раздаёт обновлённый `public/admin`.
3. Миграций БД нет. Для AI-объяснений должны быть настроены действующий OpenAI API-ключ и серверное шифрование (`INTEGRATIONS_KEY`). Стандартный локальный отчёт работает без ключа и без обращения к OpenAI.
4. Откройте Diagnostics и проверьте реальные значения очереди/backup/scheduler. Настройте наблюдение за ложными предупреждениями, если установку сознательно используют без worker или backup.
5. Нажмите «Объяснить через ChatGPT» с выбранным отклонением, проверьте влияние на месячный лимит и убедитесь, что в запросы не попадают пользовательские данные.

## Приёмочные проверки

```bash
php tools/ai-cms-diagnostics-regression.php --require-db
python3 tools/ai-cms-diagnostics-browser.py
php tools/generate-api-sdk.php --check
php bin/cajeer api:lint --strict
node admin/scripts/publish-admin-assets.mjs --check
```

`--require-db` намеренно завершится ошибкой, если отсутствует PDO SQLite. Контролируемый тест использует реальную SQLite БД для аренд токенов и fake OpenAI transport для предсказуемых ответов, **не** внешнюю сеть. Перед выпуском рекомендуется отдельная staging-проверка настоящего OpenAI API и реального production-набора БД/worker/scheduler.

## Восстановление

Функция не вводит SQL-миграций и не меняет конфигурацию. При отказе верните ранее сохранённые изменённые файлы версии 1.6.4 и пересоберите/переопубликуйте статические assets. Уже выполненные пользовательские диагностические запросы не модифицируют CMS; учтённые у OpenAI токены не подлежат откату.
