# CajeerEngine 1.7.2 — AI Actions & Approvals

## Рабочие сценарии

В AI Assistant доступны **CMS Tools** (чтение) и отдельный, выключенный по умолчанию переключатель **подготовки действий**. Включение второго переключателя разрешает OpenAI Responses API предложить одно из трёх реальных действий. Модель **никогда не применяет изменение**; соответствующий инструмент лишь создаёт в SQL предложение со сроком действия 24 часа.

| AI tool | Подтверждаемое действие | Предусловия |
| --- | --- | --- |
| `cms_action_create_draft` | Создание CMS-черновика | Существующий тип, текстовое поле схемы, корректные title/locale/slug и обязательные поля |
| `cms_action_update_seo` | Изменение `seo_title` либо `meta_description` | Существующая запись, ревизия не менялась; отдельное подтверждение опубликованного материала |
| `cms_action_support_status` | Изменение статуса обращения Support Center | Существующий тикет, актуальная ревизия |

Инструмент `cms_support_ticket_get` (только чтение) возвращает состояние и ревизию обращения **без переписки и данных посетителя**. `content:read` даёт доступ к чтению, а `content:write` требуется для подготовки и применения действий. Отсутствие разрешения не может быть обойдено указанием другого имени инструмента в запросе.

При подтверждении backend заново проверяет пользователя, роль, состояние предложенной операции, срок действия, исходную ревизию и ограничения соответствующего CMS-сервиса. Применение и изменение состояния предложения выполняются в одной SQL-транзакции. После применения повторное подтверждение отклоняется. Конфликт версии отклоняет правку без перезаписи новой ревизии. Черновики и SEO-изменения в 1.7.2 требуют **database-backed CMS content storage** для транзакционного исполнения; файловый storage остаётся доступным для чтения, но изменение через AI Actions блокируется.

## Развёртывание

1. Сделать резервную копию базы данных и `storage/`.
2. Развернуть changed-only пакет поверх полной версии **1.7.1**.
3. Выполнить `php bin/cajeer migrate` (новая миграция `0038_ai_actions.sql` для SQLite, PostgreSQL и MySQL).
4. Проверить `CONTENT_STORAGE=database` и успешность миграций Content Core.
5. Выполнить `php bin/cajeer admin:assets --check`, `php bin/cajeer api:lint --strict`, `php bin/cajeer ai:acceptance`.
6. Перезапустить PHP-FPM/OPcache и проверить доступ к AI Assistant по браузерной cookie-сессии, RBAC и CSRF.

Примеры: «Подготовь черновик в типе pages с заголовком ...»; «Предложи SEO-заголовок для записи ...»; «Предложи закрыть обращение ...». При выборе инструмента из модели в панели **AI Actions** появляется сравнение текущего состояния и предлагаемых значений. Нажать **Применить** или **Отклонить**. Никакие изменения из обычного чата не применяются без этого шага.

## API

- `GET /api/v1/ai/tools` — доступные RBAC-инструменты, включая `requires_approval`.
- `POST /api/v1/ai/chat/stream` — `tools_enabled: true`, `actions_enabled: true` для подготовки предложений; по умолчанию оба `false`.
- `GET /api/v1/ai/actions` — свои ожидающие подтверждения предложения.
- `GET /api/v1/ai/actions/{id}` — полный предпросмотр своего предложения.
- `POST /api/v1/ai/actions/{id}/approve` — `{ "confirm": true, "confirm_published": false }`, cookie-сессия, RBAC и CSRF.
- `POST /api/v1/ai/actions/{id}/reject` — `{}` и CSRF.

Содержимое предложений не записывается в AuditLogger. Аудит фиксирует ID действия, его имя и операцию. Action state хранится с владельцем, сроком действия, исходными данными, ревизией и результатом. Просмотр других пользователей недоступен. Годные к удалению записи очищаются штатным `tools/ai-retention.php` после установленного периода.

## Acceptance

Обязательные проверки в release CI: `php tools/ai-actions-integration.php --require-db` (реальные PHP/PDO/SQLite и Content Core), `python3 tools/ai-actions-sqlite-regression.py` (CAS и откат), `python3 tools/ai-actions-browser.py` (Chromium, предпросмотр, CSRF и XSS), `php tools/ai-tools-regression.php` (function calling ACL). Проверка с платным OpenAI API и подтверждение окружения production выполняются отдельно на staging.

## Rollback

При откате на 1.7.1 сначала выключить новые запросы AI Actions и дождаться завершения активных подтверждений. Не удалять `ce_ai_actions` до согласованного хранения аудита и резервных копий. SQL-миграция является добавочной, существующие `ce_ai_*` и Support-таблицы сохраняются.
