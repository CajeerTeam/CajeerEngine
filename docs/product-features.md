## Инструменты разработчика

- **REST API v1** с опубликованным [OpenAPI-контрактом](../api/openapi.yaml).
- **TypeScript SDK**, собираемый из исходников в `packages/ts-sdk`.
- **CLI `bin/cajeer`** для установки, проверок, миграций и служебных операций.
- **Extension Platform**: подключаемые компоненты, зависимости и контроль совместимости при обновлении.
- **События, очередь и scheduler** для задач, не привязанных к одному HTTP-запросу.

**Подробности:** [Расширения](extensions-platform.md) · [Queue/Scheduler](queue-scheduler.md) · [Импорт/экспорт](import-export.md)

## Идентификация, доступ и безопасность

Реализованы локальная аутентификация, сессии, API-токены, права RBAC, 2FA, проверка повторной аутентификации для чувствительных действий и опциональная интеграция SkiF4er ID через OIDC. Действия обновления и восстановления дополнительно ограничиваются серверными проверками прав, подтверждений и состояния оператора.

**Подробности:** [RBAC и assurance](identity-rbac-authentication-assurance.md) · [SkiF4er ID](identity-skif4er-id-ga-1.6.0.md) · [Production Security](security-privacy-production-1.9.5.md)

## Миграция и перенос

Migration Center организует импорт из DLE и WordPress как управляемый процесс: исследование источника, сопоставление, план, выполнение, проверка и cutover. Предусмотрены средства восстановления и проверки данных; переключение DNS или внешнего reverse proxy не выполняется магически без действий оператора.

**Подробности:** [Migration Center](migration-center.md) · [DLE](dle-migration.md) · [WordPress](wordpress-migration.md) · [Валидация и cutover](migration-validation-cutover.md)

## Эксплуатация

| Подсистема | Для чего нужна |
| :-- | :-- |
| Диагностика и observability | Оценка состояния приложения, БД и фоновых процессов |
| Queue + Scheduler | Повторяемые задачи, фоновые события, вебхуки |
| Сборка релизов | Source/dist, манифесты, хеши, отсоединённые подписи |
| Update Center | Поиск релизов, staging, подтверждённая установка через оператора |
| Backup / Rollback | Проверяемая резервная копия и явное восстановление предыдущей транзакции |
| History / Notifications | Хронология обновлений, уведомления и webhook-outbox |

> [!WARNING]
> Rollback завершённого обновления возвращает снимок приложения и данных на более раннее состояние. Записи, сделанные после обновления, могут быть утрачены. На production восстановление допустимо только после проверки backup, согласования потери данных и отдельного плана.

**Подробности:** [Observability](observability-operations.md) · [Updater 2.1.0](github-auto-updater-ga-2.1.0.md) · [Backup & Rollback](backup-rollback-integration-2.0.5.md)
