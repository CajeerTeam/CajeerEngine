# CajeerEngine 1.6.8 — AI Support Center

## Что реализовано

В версии 1.6.8 Support Center — самостоятельная работающая подсистема тикетов и переписки. **Обычные обращения и ответы операторов работают без OpenAI**. Из админки `/admin/#/support` (production static SPA) или `/support` (Nuxt) можно видеть очередь, назначать исполнителя, менять статус и приоритет, отвечать на сообщения. Доступ к просмотру требует `content:read`, к изменениям — `content:write`; на сервере обязательно проверяется активная cookie-сессия администратора, CSRF и rate limit.

Публичный виджет включается только администратором сервера. Шаблон `templates/default/layouts/app.cjr` загружает `/support/widget.js` + `/support/widget.css`; при выключенном публичном режиме виджет автоматически скрывается. Если у сайта другая тема, добавьте эти два файла в её основной шаблон. Виджет не использует внешний SDK и не раскрывает OpenAI-ключ.

Тикет открывается с именем, email, темой и сообщением. Посетителю возвращается **одноразово показанный секрет доступа** из 32 случайных байт (base64url); в SQL сохраняется только `SHA-256` этого секрета. Все последующие чтения и ответы используют заголовок `X-Support-Token`, не URL и не cookie. Виджет хранит секрет в `localStorage` текущего origin, чтобы можно было продолжить переписку после обновления страницы. Не переносите этот секрет в аналитику, URL или сторонние сервисы. При очистке localStorage доступ к тикету через виджет будет утрачен: оператор сохраняет историю в админке.

### Операции

- Публичный интерфейс: `GET /api/v1/public/support/config`, `POST /api/v1/public/support/tickets`, `GET /api/v1/public/support/tickets/{id}`, `POST /api/v1/public/support/tickets/{id}/messages`, `POST /api/v1/public/support/tickets/{id}/handoff`.
- Для оператора: `GET /api/v1/support/tickets`, `GET /api/v1/support/tickets/{id}`, `PATCH /api/v1/support/tickets/{id}`, `POST /api/v1/support/tickets/{id}/messages`, `POST /api/v1/support/tickets/{id}/ai-draft`.
- Статусы: `open` (в очереди), `waiting` (ответ отправлен, ждём посетителя), `resolved` (решено), `closed` (закрыто, последующие сообщения запрещены).
- Приоритеты: `low`, `normal`, `high`, `urgent`. Назначение производится по UUID активного CMS-пользователя. Обновление статуса/назначения требует `expected_revision` для защиты от конфликтов с другим оператором/посетителем.

Решение о закрытии принимает оператор. После AI-ответа посетитель может запросить человека, и тикет вновь появится в активной очереди. Автоответ не закрывает тикет. При ответе оператора тикет переходит в `waiting`, а при последующем сообщении посетителя — обратно в `open`.

## Конфигурация

Сначала обновите полную установленную 1.6.7 до 1.6.8 с сохранением пользовательских `.env`, `storage` и БД. Перед обновлением выполните резервное копирование. Добавьте в `.env`:

```dotenv
SUPPORT_PUBLIC_ENABLED=1
SUPPORT_AUTO_REPLY_ENABLED=0
SUPPORT_PUBLIC_AI_MONTHLY_TOKENS=50000
```

`SUPPORT_PUBLIC_ENABLED=1` включает публичную форму и виджет. Без этой настройки публичное создание тикетов заблокировано, но операторы видят имеющиеся обращения.

`SUPPORT_AUTO_REPLY_ENABLED=1` *опционально* включает платный автоматический ответ по опубликованным публичным документам после создания тикета. Для него требуется настроенный OpenAI API-ключ в **AI Assistant**, доступ к Responses API и рабочая база знаний. Автоответ ставится в существующую долговременную очередь `ai.support.reply`, поэтому получение секретного токена гостем не зависит от задержек OpenAI. Для его выполнения должен работать `php bin/cajeer queue:work --limit=10` (или штатный worker service). В режиме без активного worker тикет остаётся в очереди оператора, но автоматического ответа не будет; операторские ответы доступны независимо от AI. Для публичного AI действует отдельный месячный бюджет `SUPPORT_PUBLIC_AI_MONTHLY_TOKENS` и ограничения на создание обращений (3/IP/час, 10/IP/сутки); превышение бюджета и сбои провайдера не удаляют тикет и не мешают человеку ответить.

При ручной AI-подсказке оператор тратит собственный общий бюджет токенов AI из версии 1.6.1. Черновик нельзя отправить без подтверждения: текст попадает в поле ответа для проверки, а сохранение производится только после нажатия «Отправить».

### Ограничения приватности

AI получает *только* фрагменты опубликованных **публичных** документов Knowledge Base, актуальность источников и исходных CMS-ревизий проверяется до и после генерации. Внутренние документы и неопубликованные черновики не передаются в OpenAI. Вопрос очищается от email и некоторых форматов ключей доступа перед отправкой, но это не универсальный DLP-фильтр: сообщайте посетителям, чтобы не отправляли пароли и конфиденциальные данные. В тикетах сохраняются имя, email и текст переписки, поэтому требуется политика хранения/удаления персональных данных и ограничение доступа к БД. Публичные AI-ответы со ссылками на изменённые или недоступные источники скрываются при последующем чтении.

### Обеспечение безопасности

- Гостевые тикеты доступны только по высокоэнтропийному bearer capability. Права администратора из гостевого токена не выводятся.
- Публичные POST-запросы требуют JSON, Origin проверяется, CORS не включён, пользовательские cookie не передаются.
- Контроль rate limit выполняется на стороне сервера, а HTML из обращений, ответов и документов выводится в интерфейсе как текст.
- В audit фиксируются операторские изменения без токенов, тело сообщений не логируется в журнале аудита.
- Публичные документы проверяются по статусу, видимости, индексу и ревизии. Несоответствия приводят к блокировке AI-ответа, но не блокируют ручную поддержку.

## SQL и развёртывание

1. Сохраните резервную копию БД и файлов (включая `storage/`).
2. Разверните файлы поверх **полной** 1.6.7; не заменяйте `.env`.
3. Выполните `php bin/cajeer migrate`. Миграция `0036_ai_support_center.sql` для SQLite, PostgreSQL и MySQL создаёт `ce_support_tickets` и `ce_support_messages` с индексами и внешним ключом.
4. Запустите worker, если используете фоновые AI-ответы. Включите `SUPPORT_PUBLIC_ENABLED=1`, затем при необходимости `SUPPORT_AUTO_REPLY_ENABLED=1` после отдельной staging-проверки OpenAI.
5. Перезапустите PHP-FPM и очистите OPcache. Проверьте публичный виджет и админку.
6. Создайте тикет, ответьте из панели оператора, проверьте handoff и статус, затем закройте тикет. Проверка через две разные браузерные сессии рекомендуется.

### Acceptance

```bash
php tools/ai-support-integration.php --require-db
python3 tools/ai-support-browser.py
php bin/cajeer api:lint --strict
php tools/generate-api-sdk.php --check
node admin/scripts/publish-admin-assets.mjs --check
```

Интеграционный тест использует настоящий `PDO SQLite`, транзакции, криптографически случайные гостевые токены, действующий индекс Knowledge Base и детерминированную замену OpenAI-транспорта. В release CI он обязателен. На staging дополнительно проверьте настоящую OpenAI-модель при включённом auto-reply и установленные права на локальное файловое хранилище rate limiter.

## Rollback

Код 1.6.7 не использует новые таблицы. До отката сделайте резервную копию обращений, отключите публичный виджет и auto-reply, восстановите файлы 1.6.7. **Не удаляйте `ce_support_tickets` и `ce_support_messages` без экспорта данных и отдельного согласования**: иначе переписка будет необратимо потеряна. При возвращении 1.6.8 можно продолжить работу с сохранёнными таблицами и секретами доступа посетителей.
