# CajeerEngine 1.6.7 — AI Knowledge Chat / RAG

## Изменение

Действующий (не демонстрационный) RAG-чат работает поверх базы знаний 1.6.6 и существующего OpenAI Responses API. Он не использует внешний векторный сервис: локальный **лексический инвертированный индекс** `ce_kb_terms` ищет и ранжирует текущие фрагменты документов. Поддерживается поиск по кириллице без `mbstring`, Markdown и импортированным CMS-страницам. Семантические embeddings и полнотекстовый внешний поиск в этой версии не заявлены.

Для каждого вопроса сервер:

1. Проверяет действующую административную cookie-сессию, `content:read`, CSRF и rate limit (6 запросов/минуту на пользователя).
2. Выбирает максимум 6 релевантных фрагментов только из **опубликованных, проиндексированных** документов. Для CMS-синхронизации проверяет текущее состояние и ревизию исходной страницы.
3. В режиме `public` исключает внутренние документы на SQL-уровне. Режим `all` разрешён только аутентифицированным пользователям с `content:read` (тот же доступ, что у раздела Knowledge Base). Внешнего публичного RAG endpoint нет.
4. Если материалов не найдено, возвращает сообщение об отсутствии подтверждённых данных **без вызова OpenAI и расхода токенов**.
5. Резервирует токены в общем помесячном бюджете AI и отправляет выбранные ограниченные фрагменты через существующий TLS-защищённый OpenAI Responses API. Документы трактуются как недоверенные данные, а не системные команды.
6. Принимает ответ лишь с маркерами источников `[[S1]]`…`[[S6]]`, проверяет номера, удаляет неподдерживаемые маркеры и сверяет актуальность документов после генерации. Если ссылки отсутствуют или источник обновлён, возвращает отказ вместо незаземлённого текста.
7. В транзакции сохраняет вопрос, ответ, список процитированных UUID/ревизий и списание фактических токенов. При ошибке API резерв освобождается. Прерванные резервы восстанавливаются существующим механизмом `AiBudgetLease` (TTL 180 с).

На чтении сохранённых ответов сервер заново проверяет источники. Если документ удалён, архивирован, изменён или перестал быть доступным в выбранном scope, **весь соответствующий ответ скрывается**. История изолирована по `user_id`; пользователь не может читать, оценивать или удалять чужие диалоги.

## Развёртывание с 1.6.6

1. Сделайте резервную копию БД и `storage`.
2. Наложите только изменённые файлы поверх полной 1.6.6.
3. Выполните миграции штатной командой: `php bin/cajeer migrate`. Создаётся `0035_ai_knowledge_chat.sql` для SQLite, PostgreSQL или MySQL, таблицы `ce_ai_kb_conversations` и `ce_ai_kb_messages`.
4. Проверьте, что БД и `ce_ai_usage`, `ce_ai_editor_jobs`, `ce_kb_*` доступны, а PHP ext-curl и действующий API-ключ OpenAI настроены в AI Assistant.
5. Перезапустите PHP-FPM и очистите OPcache. Обновите `/admin/` (production static SPA публикуется вместе с архивом).
6. Откройте **AI Knowledge Chat / RAG**, выберите видимость и язык, задайте вопрос по опубликованным документам. Проверьте переход по источнику в Knowledge Base, отзывы и удаление диалога.

## Проверки перед production

```bash
php tools/ai-knowledge-chat-integration.php --require-db
python3 tools/ai-knowledge-chat-browser.py
php tools/ai-knowledge-integration.php --require-db
php tools/generate-api-sdk.php --check
node admin/scripts/publish-admin-assets.mjs --check
php bin/cajeer api:lint --strict
```

Реальный запрос к OpenAI необходим на staging; интеграционный тест использует детерминированную замену транспорта, но настоящие SQL-операции, лимиты, ревизии и скрытие недоступных ответов. Не включайте RAG для гостевых пользователей — API является административным.

## Ограничения и защита информации

- Передача документа в OpenAI — внешний обмен данными. Если внутренние документы нельзя передавать провайдеру, выберите **Только публичные** или запретите предоставлять такие права пользователям.
- Нельзя считать ссылки математическим доказательством истинности текста. Модель может ошибаться при интерпретации фрагментов; проверяйте критичные рекомендации по оригиналу.
- Специальное исполнение команд, автоматическое редактирование CMS, генерация ответов посетителям без авторизации и embeddings не реализованы.
- Индексируется до 220 фрагментов на документ; длинные документы за пределами лимита не участвуют в поиске. При слабом лексическом совпадении запрос можно уточнить.
- При миграции назад на 1.6.6 код 1.6.6 игнорирует RAG-таблицы; удалять их не обязательно. Не удаляйте таблицы без отдельного backup.
