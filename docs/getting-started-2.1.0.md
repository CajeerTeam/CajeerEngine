# Начало работы с CajeerEngine 2.1.0

От первого знакомства до проверенной установки. Выберите путь в зависимости от цели: **разработка из исходников** или **установка подготовленного дистрибутива**.

**[← Документация](README.md)** · **[Продукт](product-overview.md)** · **[Обновление](releases/upgrade-2.1.0.md)**

---

## 01. Выберите тип установки

| Сценарий | Исходный материал | Для чего подходит |
| :-- | :-- | :-- |
| Разработка и локальный тест | Исходный репозиторий, Composer-зависимости | Изучение, разработка, тесты, локальная SQLite |
| Развёртывание сайта | Подписанный `cajeerengine-2.1.0-dist.zip` | Сервер с выполненными требованиями и проверенной процедурой |
| Обновление действующей CMS | Подписанный `dist.zip` + механизм обновления | Staging-проверка, backup, отдельный оператор и подтверждение |

> [!IMPORTANT]
> GitHub `Source code (zip)` и файл `*-source.zip` **не равнозначны** подготовленному `*-dist.zip`. Для production нужен проверенный дистрибутив, а не архив с исходниками.

## 02. Системные требования

**Минимум из метаданных релиза:** PHP `>=8.4.1 <9.0`, расширения из `composer.json`, PDO и драйвер выбранной БД. Для сборки исходников — Composer 2; для работы со сборкой frontend/SDK — Node.js 22 в CI-профиле проекта.

| Сервис | Требование или рекомендация |
| :-- | :-- |
| PHP | 8.4.1+ в диапазоне до 9.0; CLI и PHP-FPM для рабочего сервера |
| Production БД | PostgreSQL 17+; PostgreSQL 18+ рекомендуется |
| Локальная БД | SQLite 3.40+ для demo/local |
| Дополнительные БД | MySQL 8.4+ или MariaDB 10.11+ — требуют отдельной проверки профиля |
| Production web | Nginx с TLS, Linux/systemd, отдельные worker и scheduler |
| Права доступа | `public/` — web root; секреты и резервные копии — вне публичного каталога |

**Полный профиль:** [Production Deployment](production-deployment.md) и [операционная приёмка](operations-acceptance-1.8.8.md). Не считайте минимальный набор PHP-расширений достаточным для всех интеграций — проверяйте `composer check-platform-reqs` и нужный профиль.

## 03A. Локальный запуск из исходников

```bash
# В корне распакованного репозитория
composer install --no-interaction --prefer-dist
composer check-platform-reqs

# Локальная SQLite-установка с вводом параметров в интерактивном режиме
php bin/cajeer install --sqlite --interactive

# Диагностика после установки
php bin/cajeer doctor
php bin/cajeer admin:assets --check
```

Настройте локальный веб-сервер с корнем сайта `public/` и открывайте `/admin/` по адресу вашей установки. Не публикуйте тестовую SQLite-инсталляцию как доказанно готовую production-среду. При работе с исходниками ассеты Static Admin SPA уже присутствуют в `public/admin`, но могут потребовать проверки согласованности с кодом.

При необходимости пересобрать интерфейс: [руководство по опубликованным админ-ассетам](admin-rendering.md) и `admin/scripts/publish-admin-assets.mjs`. Не запускайте произвольную сборку на production-хосте, где должен использоваться готовый dist.

## 03B. Установка готового дистрибутива

1. Откройте [официальный релиз 2.1.0](https://github.com/CajeerTeam/CajeerEngine/releases/tag/v2.1.0) и выберите `cajeerengine-2.1.0-dist.zip` вместе с `.sha256`, `.sig` и манифестом.
2. Получите **доверенный публичный ключ Ed25519 по независимому доверенному каналу**. Хеш со страницы загрузки позволяет проверить целостность, но не доказывает происхождение без доверия к издателю.
3. Проверьте ZIP и сопровождающие данные по [регламенту релиза](production-certification.md), подготовьте систему и резервные копии.
4. Разместите `dist.zip` на сервере через контролируемую процедуру, настройте `public/` как document root и права runtime-каталогов.
5. Используйте [профиль развёртывания](production-deployment.md) либо проверенный [web/CLI installer](install.md), соответствующий вашему серверу.
6. После установки проверьте `/admin/`, диагностику, соединение с БД, публичные страницы и фоновые процессы.

> [!CAUTION]
> В примерах старых эксплуатационных руководств могут встречаться архивы `1.8.8`. Используйте имя и версию **фактически выбранного** дистрибутива 2.1.0, не копируя старую команду с её версией или SHA-256. Не запускайте деструктивные host-smoke тесты на рабочем сервере.

## 04. Контрольный список после установки

- [ ] Версия приложения совпадает с ожидаемой (`VERSION` / `release.json`).
- [ ] `php bin/cajeer doctor` не сообщает о блокирующих ошибках.
- [ ] Вход в `/admin/` и права выбранной роли работают.
- [ ] База данных, миграции, медиа и публичные маршруты отвечают корректно.
- [ ] Worker и scheduler действительно запущены, если используются очередь и фоновые задачи.
- [ ] Бэкап проверен восстановлением **на отдельном стенде**, ключ шифрования сохранён отдельно.
- [ ] Если используется Admin Update Center, оператор реально публикует свежий heartbeat и не находится в `recovery_required`.
