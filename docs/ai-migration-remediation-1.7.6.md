# CajeerEngine 1.7.6 — AI Migration Remediation

## Реальная область применения

Это отдельный модуль подтверждаемых исправлений поверх Migration Center и AI Migration Copilot. Он читает реальные записи в `ce_migration_seo_path_evidence` и состояние целевого CMS. Модель OpenAI **не определяет SQL, target path или команду**, исполняемую сервером. Для подготовки и выполнения исправлений OpenAI API не требуется.

Поддерживаются две операции:

1. **restore_redirect** — создать отсутствующий активный 301-редирект из прежнего URL в опубликованный целевой URL, если точное соответствие записано в карте SEO-миграции. Не перезаписывает действующие правила, не захватывает занятые маршруты и не создаёт переходов на черновики.
2. **rebuild_routes** — восстановить неконсистентный индекс публичных маршрутов из актуальных объектов CMS и редиректов под общей блокировкой писателей. Это не меняет записи и DNS, но перестраивает поисковую проекцию. Запускайте только после резервного копирования.

Не производится автоматическое восстановление отсутствующих файлов, переписывание редакторских ревизий, исправление невалидных query-URL, повторный импорт контента, удаление дублей, DNS-cutover и произвольные операции с файлами. Для них требуется соответствующая операторская сверка и исходный backup; недостоверные «исправления» запрещены.

## Обновление с 1.7.5

1. Сделайте резервную копию БД и файлов CMS, проверьте возможность восстановления.
2. Обновите только изменённые файлы, запустите `php bin/cajeer migrate` (миграция `0039_ai_migration_remediation.sql` для SQLite, PostgreSQL и MySQL).
3. Перезапустите PHP-FPM и очистите OPcache; пересоздайте cache/proxy ресурсы по вашим стандартным инструкциям.
4. Проверьте `php bin/cajeer api:lint --strict`, `php bin/cajeer admin:assets --check`, `php tools/ai-migration-remediation-regression.php`.
5. В админке откройте Migration Center → AI Migration Copilot (или Nuxt `/migration-copilot`), выберите завершённый проект, запустите диагностику, затем откройте доступные исправления.

## Операторский цикл

- **Просмотр:** `GET /api/v1/ai/migration/projects/{id}/remediation?offset=0`. Возвращает максимум 100 проверенных записей карты за запрос, указатель следующей партии, ожидающие действия и историю решений текущего пользователя. Схема не содержит исходных credentials.
- **Подготовка:** `POST /api/v1/ai/migration/projects/{id}/remediation`, JSON `{ "kind": "restore_redirect", "source_path": "/old-article" }` или `{ "kind": "rebuild_routes" }`. Target никогда не принимается от браузера: сервер получает его из сохранённой карты миграции. Предложение сохраняется с TTL 1 час, владельцем и точным снимком изменения. Данные CMS при подготовке не меняются.
- **Подтверждение:** `POST .../remediation/{proposal}/apply`, тело `{}`. Требует действующую браузерную сессию, `migration:run` + `migration:write`, CSRF и **свежее повторное подтверждение входа**. Перед записью ещё раз проверяются сохранённая карта, текущая цель, отсутствие чужого редиректа и консистентность маршрутов. Запись, резервирование одноразового предложения и пересборка публичного индекса происходят в общей транзакции и под общей блокировкой писателей. При отказе транзакция откатывается.
- **Отклонение:** `POST .../remediation/{proposal}/reject` с телом `{}`. Заявка теряет возможность применения.
- **Откат 301:** `POST .../remediation/{proposal}/rollback` с телом `{}`. Требует прежнего владельца, расширенных прав и свежей аутентификации. Откат возможен только для **всё ещё неизменённого редиректа** с исходным UUID и `hit_count=0`. Отправивший реальные запросы либо изменённый человеком редирект можно восстановить только вручную по плану владельца сайта. Пересборка индекса не откатывается к заведомо повреждённому состоянию.

После любых действий повторите Copilot Report и полноценную операторскую проверку `php bin/cajeer migration:validate PROJECT_ID`. Отсутствие находок в первых 100 записях не означает отсутствие ошибок во всём проекте. Для больших карт используйте `offset` и следующие партии.

## Ограничения и ошибки

- Актуальная карта SEO-миграции и опубликованная целевая страница обязательны. Запрещены пути `/api`, `/admin`, `//host`, query URL, URL с запрещённым кодированием и коллизии с маршрутами.
- Если кто-то изменит карту, цель, существующий редирект либо статус предложения, применение будет отвергнуто без записи. При повторном запросе вернётся конфликт, а не вторая запись.
- Операции выполняются в SQL-backed режиме CMS; тестировать их с file-backed публичным routing не следует. Необходимы таблицы маршрутов и редиректов.
- Реальное восстановление данных из резервной копии невозможно без самого backup и проверки его целостности; система ничего не выдумывает из текста AI.
- В журнал пишутся идентификаторы проекта/предложения и тип действия, без секретов подключения. Хранятся исходная и итоговая записи для контроля и ревью.

## CI и эксплуатационная проверка

- `python3 tools/ai-migration-remediation-sqlite-regression.py` — SQL-миграция, конкурентный CAS, откат аварийной записи и однократность.
- `php tools/ai-migration-remediation-integration.php --require-db` — обязательный PHP/PDO acceptance: рабочие CMS-маршруты, восстановление редиректа, конфликт, недоверенное сопоставление, транзакционный rollback, отказ в чужих предложениях, обратимость 301 и восстановление индекса.
- `php tools/ai-migration-remediation-regression.php` — маршруты, RBAC, повторное подтверждение.
- `python3 tools/ai-migration-remediation-browser.py` — Chromium, предпросмотр, подтверждение и откат, XSS и CSRF.

До production-развёртывания обязательны зелёный CI с `pdo_sqlite`, staging с тем же драйвером БД, реальными данными завершённой миграции и тест восстановления резервной копии. Этот модуль не выполняет платные запросы к OpenAI.
