# SkiF4er ID — CajeerEngine 1.5.2

## Working scope

Backend OIDC Authorization Code + PKCE S256, real TLS exchanges against `https://id.skif4er.ru/realms/skif4er`, discovery, JWKS / RS256 ID-token validation, one-time browser-bound SQL transactions, explicit operator links, and existing local HttpOnly `ce_session` issuance. No OAuth tokens or passwords are written into the browser or logs.

**This release does not implement self-service account linking, registration, refresh-token sessions, SSO/backchannel logout or external bearer tokens for the API.** These remain separate releases. Local login and RBAC are preserved. An unlinked subject is not allowed in, even if its verified email matches a local account.

## Deployment

1. Register a separate Keycloak confidential OIDC client in realm `skif4er` at `https://id.skif4er.ru`. Enable Standard Flow and PKCE S256; disable implicit and password grants. Specify exact redirect `https://cms.example.com/auth/oidc/callback`. The client secret must only reside on the backend.
2. Set the canonical HTTPS `APP_URL` and `SKIF4ER_ID_ENABLED=true`, `SKIF4ER_ID_CLIENT_ID=...`, `SKIF4ER_ID_CLIENT_SECRET=...` in the protected `.env`. Keep a valid **32-byte** `base64:` `APP_KEY` / `INTEGRATIONS_KEY` or a dedicated `SKIF4ER_ID_TRANSACTION_KEY`. Never regenerate the key while logins are in flight.
3. Run `php bin/cajeer migrate` to create `ce_oidc_transactions` and `ce_oidc_identities` (SQLite / PostgreSQL / MySQL). PHP `curl`, `openssl`, `sodium`, `pdo` and your DB driver must be available.
4. Log into SkiF4er ID with the intended user on the identity provider, obtain their **verified `sub` claim** through a trusted operator workflow (do not take a caller-supplied email or arbitrary browser value), then run on the server:

   ```bash
   php bin/cajeer identity:link-user LOCAL_USER_UUID VERIFIED_OIDC_SUB --yes
   ```

   The CLI checks the local account is active, ensures the pair is not linked to a different user, and writes an audit record.
5. Restart the PHP worker. Visit `/admin/` or `/admin/#/login`. The button is shown only when the provider is enabled. Successful callback returns to `/admin/` and issues the existing HttpOnly cookie, which is subject to normal CSRF and RBAC protections.

## Security guarantees / behavior

- Fixed issuer and pinned HTTPS Keycloak endpoints; redirects in outbound token/discovery requests are disabled. A valid RS256 JWKS key is required. Claims checked: `iss`, `aud`, `azp`, `exp`, `iat`, `nbf`, `nonce`, `sub`.
- PKCE, `state`, `nonce` and random browser binding are generated server-side. The verifier is encrypted at rest; the transaction expires after five minutes and is **consumed exactly once** before exchanging the code. Invalid callbacks do not issue a new session.
- Existing local accounts, passwords, RBAC permissions and active sessions remain unchanged. The local session token is generated by the existing `ApiTokenRepository` and is never returned in callback responses.
- Accounts with local TOTP enabled require the external ID token to provide recognized MFA evidence in `amr` (`mfa`, `otp`, `hwk` or `swk`); if not present, login is denied. Configure Keycloak protocol mappers and MFA policy accordingly. Sensitive actions still require existing local reauthentication.
- Use trusted HTTPS termination so Symfony correctly detects the request as secure. In this release callback and authorization routes refuse HTTP. Backups must preserve your configured secret encryption key.
- For existing external users, no account is created and no permission is imported. A linked disabled account cannot authenticate. Operator linking is deliberately separate from login in this release.
- Keycloak SSO logout is **not** propagated to local CajeerEngine sessions in 1.5.1. Local logout revokes the local session. In high-security environments reduce `SESSION_TTL_DAYS` until unified-session and back-channel logout versions are deployed.

## Testing

`php tools/oidc-regression.php` exercises RS256 signing/verification with generated keys and a controlled HTTP response transport; `python3 tools/oidc-sqlite-regression.py` tests the real SQLite schema, unique identities and single-use transaction. `php tools/oidc-db-regression.php --require-db` checks actual PDO SQLite one-time state and ciphertext round-trips in release CI. `python3 tools/oidc-admin-browser-regression.py` checks the production login button in Chromium. These tests do not replace an end-to-end trial against an operator-registered Keycloak client; production activation requires that separate trial.

## Account linking & opt-in provisioning (1.5.2)

After signing in with a **local** account (HttpOnly `ce_session`), open `/admin/#/identity` (or the Nuxt `/identity` page). The linking form requires the current local password and, if enabled, the current 2FA code. The backend POSTs to `/api/v1/identity/link/start`, verifies the local secret using `AuthService::confirmSensitiveAction`, then creates an expiring, one-use OIDC transaction bound to that same local session ID. Only after SkiF4er ID supplies a valid signed ID token does the backend write the issuer/subject link. The pending transaction is rejected if that local session was revoked or expired. Linking an already claimed `sub`, or reassigning an account already linked to another `sub`, fails. Never link by email alone.

`GET /api/v1/identity/account` reports the current user's link status without revealing the OIDC subject. `POST /api/v1/identity/unlink` requires local password/2FA and a CSRF-protected cookie session. Provisioned OIDC-only accounts cannot unlink until a verified local login method has been set up; this release does not implement that method.

Optional registration of **new** users is disabled by default. Set `SKIF4ER_ID_AUTO_PROVISION=true` only if external registration is intended. A missing link may then create a user only when the signed ID token has `email_verified: true`, a valid email not present in CajeerEngine, and a safe `viewer` role. A strong undisclosed password is stored via the normal PasswordHasher. Existing emails are never auto-merged or auto-linked. The generated password cannot be used to sign in; local password setup/recovery is a separate process. Disable auto-provision to require operator prelinks.

Existing local accounts, 2FA configuration, roles, API tokens and normal login remain unchanged. OAuth tokens remain server-side. OIDC registration and unlinking do **not** propagate global logout; Session Manager/Back-Channel Logout is scheduled for later releases. To run the isolated DB regression in CI, enable PHP `pdo_sqlite`, `mbstring`, `sodium` and `openssl`. Apply `0027_oidc_account_linking.sql` on SQLite/PostgreSQL/MySQL before enabling new functionality.
