# CajeerEngine 1.6.6 — AI Knowledge Base

## Реальный функционал

В административной панели доступны **Knowledge Base** (`/admin/knowledge` в Nuxt, `/admin/#/knowledge` в static SPA), категории, документы, статус `draft`/`published`/`archived`, видимость `internal`/`public`, поиск и переиндексация. Поддерживаются:

- создание, обновление и удаление категорий; категория с документами не удаляется;
- создание и редактирование документа с обязательной проверкой `expected_revision` на изменение и удаление;
- импорт TXT, Markdown, а также **PDF с текстовым слоем**. PDF обрабатывается серверной утилитой Poppler `pdftotext`; скан без текстового слоя требует предварительного OCR вне CMS;
- ручная синхронизация опубликованных записей CMS с сохранением отдельной копии текста и идентификатора исходной ревизии;
- индексирование публикации внутри той же SQL-транзакции, удаление устаревших терминов при изменении и удалении, пошаговая переиндексация;
- индекс по Unicode-словам, языковые фильтры и разделение публичной и внутренней видимости.

**Граница релиза:** 1.6.6 — управляемое хранилище и лексический retrieval, **без** автоматического обращения к OpenAI, генерации embeddings, vector DB или RAG-ответов. Ответы на основе источников предусмотрены для 1.6.7. Индексация поддерживает SQLite, PostgreSQL и MySQL/MariaDB на уровне схем и SQL-кода.

## Безопасность и публикация

Управление доступно **только активной административной браузерной сессии**. Чтение требует `content:read`, изменение — `content:write`; операции изменения дополнительно проходят CSRF middleware и лимит частоты. Публичного маршрута чтения базы знаний нет. **`public` — это классификация документа для будущего публичного retrieval, не автоматическое разрешение анонимным пользователям.** Документы с `status != published` полностью исключаются из терм-индекса, а `visibility=internal` не возвращается при фильтре `public`.

Новым материалам присваивается `draft` и `internal` (по умолчанию). Синхронизация CMS разрешена только для *опубликованной* исходной страницы; новый синхронизированный документ остаётся **внутренним**, пока редактор не назначит ему публичную видимость. Весь CMS-индекс изолирован от обычного публичного поиска `ce_search_documents`. При изменении или снятии исходной страницы с публикации устаревшая копия исключается из результатов поиска до следующей синхронизации. CMS-связанный документ можно менять только в статусе, категории или видимости — исходное содержание не редактируется в Knowledge Base.

Импорт передаёт **base64 в JSON**, лимит исходного файла 2 МиБ, текста 128 КиБ. Запрещены путь в имени файла, недопустимый UTF-8, неподдерживаемые расширения. PDF проверяется по сигнатуре и обрабатывается отдельным процессом с ограничением времени и объёма вывода; двоичные файлы в хранилище не сохраняются. Для большего объёма загрузку нужно разбить на документы. Внешние ссылки и HTML отображаются с экранированием в SPA.

## Установка / обновление

1. Сделайте резервную копию БД и текущих файлов. Примените ZIP *changed-only* поверх полной версии **1.6.5**.
2. Запустите миграции: `php bin/cajeer migrate`. Будут созданы `ce_kb_categories`, `ce_kb_documents`, `ce_kb_chunks`, `ce_kb_terms`, **не** затрагивая публичный поисковый индекс.
3. Для импорта PDF установите Poppler (`/usr/bin/pdftotext`, например пакет `poppler-utils`). PHP должен разрешать `proc_open` и иметь доступ к `sys_get_temp_dir()`. Для TXT и Markdown дополнительный бинарник не нужен.
4. Перезапустите PHP-FPM и очистите OPcache. Проверьте, что обновлён `public/admin` вместе с манифестом assets.
5. В админке откройте **Knowledge Base**, создайте категорию и черновик, опубликуйте его с нужной видимостью, проверьте поиск, изменение с revision и удаление. Проверьте импорт MD/PDF и синхронизацию одной опубликованной страницы.
6. Для полной переиндексации используйте действие **Переиндексация** в админке (пакеты до 100 документов). При большом каталоге повторяйте по `next_offset` до `null`, не запуская одновременно несколько конкурирующих пересборок.

## Проверки и ограничения принятия

```bash
php tools/ai-knowledge-integration.php --require-db
python3 tools/ai-knowledge-browser.py
php tools/generate-api-sdk.php --check
php bin/cajeer api:lint --strict
node admin/scripts/publish-admin-assets.mjs --check
php tools/ci-check.php
```

`--require-db` — реальный SQL/транзакционный интеграционный тест с PDO SQLite. Если расширение не установлено, он **должен** завершаться ошибкой в CI; без этого аргумента тест явно печатает `SKIP`. Chromium-проверка покрывает пользовательские действия SPA и CSRF с контролируемым HTTP mock, а не заменяет проверку подключённой БД. На staging перед GA отдельно требуется протестировать выбранную production СУБД и реальный PDF с текстовым слоем.

## Восстановление

Рекомендуется сначала удалить или скрыть ссылки Knowledge Base, вернуть ранее сохранённые изменённые файлы версии 1.6.5 и восстановить backup БД при необходимости. Миграция создаёт только новые таблицы, не изменяет старые CMS-данные; удалять новые таблицы до резервного копирования и экспорта документов нельзя.
