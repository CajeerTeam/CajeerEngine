# CajeerEngine 1.7.5 — AI Migration Copilot

## Назначение

AI Migration Copilot предназначен для диагностики **результата** миграции DLE или WordPress. Он читает реальный проект Migration Center, последнюю сохранённую операторскую сверку (`ce_migration_validation`) и проверяет доступные целевые ресурсы. Переход на новый сайт, изменение DNS, импорт, синхронизация и исправление записей не выполняются из веб-интерфейса Copilot.

## Возможности

- Определение состояния завершения импорта, синхронизации и cutover по сохранённым данным.
- Вывод результатов последней операторской сверки с причиной, объектом и конкретной рекомендацией.
- Проверка актуальности 301-редиректов по сохранённой карте `ce_migration_seo_path_evidence` и WordPress query-перманентных адресов из `ce_migration_seo_query_urls`.
- Проверка наличия и SHA-256 импортированных медиафайлов из `ce_migration_media_files`, проверка соответствия индекса публичных маршрутов.
- Отображение сохранённого статуса сверки отдельно от текущих находок, чтобы изменения на сайте после cutover не маскировались старым успешным отчётом.
- Экспорт JSON отчёта для передачи администратору.
- Дополнительное объяснение через OpenAI Responses API с учётом существующего бюджета токенов, rate limit и аудитом.

Проверка в рамках одного HTTP-запроса намеренно ограничена первыми 200 сохранёнными редиректами каждого вида и 200 медиафайлами; для медиа проверяется максимум 128 МиБ хешируемых данных, отдельный файл более 32 МиБ пропускается. При ограниченном объёме выводится предупреждение. Это **не полная сертификация** миграции. Полную сверку источника и назначения выполняет операторская CLI-команда.

## Работа в административной панели

1. Откройте **Migration Center** в статической админке или **AI Migration Copilot** в Nuxt.
2. Выберите ранее созданный проект DLE/WordPress и выполните **Проверить проект**.
3. Изучите приоритет, код, затронутый объект и рекомендуемую ручную проверку. Смотрите на дату последнего `migration:validate`: старый отчёт не подтверждает состояние исходного сайта сегодня.
4. При необходимости нажмите **Объяснить через OpenAI**. Эта операция платная и требует настроенного OpenAI API-ключа.
5. Используйте **Экспорт JSON** для технической приёмки и повторите диагностику после ручного исправления.

## API

- `GET /api/v1/ai/migration/projects/{id}/report` — локальная проверка без OpenAI.
- `POST /api/v1/ai/migration/projects/{id}/explain` — платное AI-объяснение, тело `{}`.

Оба маршрута требуют прав `migration:read` и активной браузерной сессии. POST дополнительно защищён CSRF. Для чтения действует лимит 5 запросов за 60 секунд на пользователя, для AI — 3 за 60 секунд.

В OpenAI передаются только тип источника, агрегированные числовые счётчики, коды проблем, результаты технических проверок и предупреждения. **Не передаются** имена файлов, исходные URL, идентификаторы проектов, пароли БД, токены WordPress или исходные отчёты целиком. Ключ OpenAI остаётся на сервере. Ответ AI не запускает команды.

## Развёртывание

1. Сделайте резервную копию БД и `storage/app/migration`.
2. Наложите changed-only ZIP поверх полной версии `1.7.4` с сохранением путей.
3. Выполните `php bin/cajeer api:lint --strict` и `php bin/cajeer admin:assets --check`.
4. Перезапустите PHP-FPM / очистите OPcache, затем проверьте отображение Copilot под ролью с `migration:read`.
5. После завершения основной миграции используйте серверную команду `php bin/cajeer migration:validate <project_id>` с соблюдением требований эксклюзивного операторского режима и maintenance.
6. Проверьте запуск Copilot на проекте с выполненной сверкой, а затем проверьте пояснение OpenAI при наличии API-биллинга.

Новых SQL-миграций не требуется: используются уже существующие таблицы 1.7.4.

## Проверки

```sh
php tools/ai-migration-copilot-regression.php
python3 tools/ai-migration-copilot-browser.py
php bin/cajeer api:lint --strict
php bin/cajeer admin:assets --check
```

Проверки на реальной БД PostgreSQL/MySQL, полном наборе файлов и действующем OpenAI API требуют целевого staging-окружения. Прохождение синтаксиса, OpenAPI и браузерного теста не доказывает успешную реальную миграцию.

## Откат

Используйте резервную копию исходной версии 1.7.4 и восстановите файлы, изменённые в рамках 1.7.5. Данные миграции Copilot не изменяет и отдельной SQL-миграции для отката нет. Не удаляйте существующие миграционные отчёты или исходные файлы во время отката кода.
