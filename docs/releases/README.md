## Как читать релизную документацию

1. **Что нового** — кратко описывает продуктовые изменения, техническое поведение и ограничения.
2. **Порядок перехода** — показывает безопасную последовательность подготовки, подтверждения и контроля.
3. **Операционные инструкции** — определяют детали для конкретного профиля deployment, ключей и восстановления.
4. **Release evidence** — подтверждает CI/подписи/приёмку именно тех байтов, которые вы устанавливаете.

## Политика выпуска

Метаданные текущей версии хранятся в [`VERSION`](../../VERSION) и [`release.json`](../../release.json). В `release.json` указаны SemVer, канал `stable`, Engine API `1.1`, а также `lts_ready: false`. Сам по себе `stable` **не** является заявлением о LTS или универсальной production-поддержке. Доверяйте только проверенному артефакту, процессу его выпуска и приёмке конкретной установки.
