| Каталог или файл | Назначение |

| `core/Kernel/` | Сборка приложения и контейнер зависимостей |
| `core/Http/`, `core/Api/` | HTTP, middleware, REST-контроллеры и маршрутизация |
| `core/Content/`, `core/Cms/`, `core/Media/` | Данные материалов, CMS и файлов |

## Поток запроса

1. Web-сервер передаёт запрос публичной точке входа в `public/`.
2. HTTP-слой применяет middleware, распознаёт маршрут и проверяет применимые правила аутентификации и авторизации.
3. Контроллер использует сервисы ядра, репозитории, файлы или внешнего провайдера по конфигурации.
4. Клиент получает API-ответ либо HTML через публичный рендерер; длительные операции при необходимости делегируются worker/scheduler.

Список публичных контрактов — в [`api/openapi.yaml`](../api/openapi.yaml); он важнее схематичных примеров на этой странице.

## Отдельный контур обновлений

Обновление **не** выполняется PHP-FPM-процессом по нажатию кнопки в браузере.

```text
GitHub Releases
      │ обнаружение и выбор
      ▼
Admin Update Center ──► подтверждённый одноразовый запрос
                                      │
                                      ▼
                            non-root Update Operator
                                      │
                   подпись + манифест + preflight
                                      │
                       backup → install → postcheck
                                      │
                       journal / статус / уведомление
```

В версии 2.1.0 постановка новых запросов зависит от **реального актуального heartbeat** оператора. Если он отсутствует или есть маркер незавершённого восстановления, HTTP-запрос на действие блокируется. При этом [root-managed deployment preset](production-deployment.md) не совместим с non-root updater автоматически: права и владение должны быть согласованы для конкретного сервера.

## Дизайн и эксплуатационные границы

- Доступы, настройки и секреты должны проверяться на серверной стороне; UI не является границей безопасности.
- Работа с MySQL/MariaDB, SQLite и PostgreSQL включает разные особенности миграций и восстановления; успешная проверка одного драйвера не подтверждает другой.
- Queue/scheduler не следует считать работающими по одному факту установки CMS — процессы запускаются и контролируются отдельно.
- Указанный production-профиль — **single-node Linux**. Кластеры, произвольные плагины и нестандартные файловые хранилища требуют отдельной квалификации.
- Точность SLO, p95/p99 и допустимой нагрузки нужно измерять на инфраструктуре проекта, а не выводить из наличия нагрузочных тестов в CI.
