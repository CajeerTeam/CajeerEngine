# Политика безопасности CajeerEngine

## Сообщение об уязвимостях

Если вы нашли уязвимость в CajeerEngine, не публикуйте её в открытых issues, обсуждениях, pull/merge requests, чатах или социальных сетях до выхода исправления.

Для ответственного раскрытия используйте:

```text
security@cajeer.ru
```

Если проблема связана со злоупотреблением, вредоносной активностью, спамом или нарушением правил инфраструктуры:

```text
abuse@cajeer.ru
```

Для юридически значимых вопросов:

```text
legal@cajeer.ru
```

## Что указывать в сообщении

По возможности включите:

- краткое описание проблемы;
- затронутую версию CajeerEngine;
- затронутый компонент;
- шаги воспроизведения;
- ожидаемое и фактическое поведение;
- возможное влияние;
- proof of concept, если он безопасен и не разрушителен;
- рекомендации по исправлению, если они есть.

Не прикладывайте эксплойты, которые могут нанести вред пользователям, инфраструктуре или данным.

## Поддерживаемые версии

Начиная с `1.0.5`, актуальная stable-ветка получает исправления безопасности в рамках SemVer/security releases.

Общее правило:

- актуальная development/stable-ветка получает исправления безопасности;
- LTS-ветки будут отдельно объявляться в release policy;
- неподдерживаемые версии могут не получать исправления.

## Процесс обработки

Обычный процесс:

1. Получение сообщения.
2. Первичная оценка.
3. Воспроизведение проблемы.
4. Классификация риска.
5. Подготовка исправления.
6. Проверка исправления.
7. Выпуск security release.
8. Публикация информации после устранения риска.

## Координация раскрытия

Проект придерживается ответственного раскрытия.

До публикации исправления не раскрывайте:

- технические детали эксплуатации;
- proof of concept;
- приватную переписку;
- сведения о затронутых пользователях;
- детали инфраструктуры.

## Security releases

Исправления безопасности выпускаются как отдельные security releases в рамках SemVer.

Формат конкретных релизов определяется мейнтейнерами Cajeer Team.

## Области безопасности

Политика распространяется на:

- ядро CajeerEngine;
- REST API;
- OpenAPI-контракты;
- CLI;
- Web Installer;
- Admin UI;
- extension API;
- registry/update system;
- систему прав и ролей;
- API-токены;
- signed payloads;
- webhooks;
- импорт/экспорт;
- storage abstraction;
- queue/scheduler;
- шаблонизатор `.cjr`;
- sandbox выполнения шаблонов.

## Не считаются уязвимостями без дополнительного контекста

Обычно не считаются уязвимостями:

- отсутствие security headers в локальной dev-среде;
- сообщения об устаревших зависимостях без доказанного влияния;
- self-XSS без сценария эксплуатации;
- проблемы, требующие полного административного доступа;
- rate limit замечания без практического сценария злоупотребления;
- результаты автоматических сканеров без подтверждения.
