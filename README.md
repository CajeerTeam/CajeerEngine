## CajeerEngine в двух словах

CajeerEngine объединяет управление материалами, программный доступ к контенту и сервисы эксплуатации. Вы создаёте структуру и публикации в админке, интегрируете контент через REST API, подключаете расширения и контролируете жизненный цикл установки — от миграций до восстановления из резервной копии.

| Для редакции | Для разработчика | Для администратора |
| :-- | :-- | :-- |
| Материалы, ревизии, медиа и публикации | REST API, OpenAPI, SDK, расширения | Диагностика, аудит, очереди и резервные копии |
| SEO, локализация и управление страницами | Собственное PHP-ядро, CLI и события | Проверенные обновления и контролируемый rollback |
| AI-инструменты и аналитика при настройке интеграций | Импорт и миграция существующих сайтов | Роли, 2FA, SSO и контроль доступа |

> [!IMPORTANT]
> **2.1.0 — опубликованный стабильный релиз проекта.** Наличие релиза и успешного CI не означает автоматического допуска любого сервера к эксплуатации. Для конкретной установки нужны проверенный подписанный `dist`, рабочая среда и staging-приёмка. [Что проверять перед production →](docs/releases/upgrade-2.1.0.md)

## Релиз 2.1.0 · GitHub Auto-Updater GA

Главное в этой версии — **операционная готовность встроенного центра обновлений**. Система проверяет реальный heartbeat отдельного non-root оператора и не разрешает новое действие, если оператор недоступен, его статус устарел или требуется восстановление.

| Изменение | Практический результат |
| :-- | :-- |
| **Проверка готовности оператора** | Администратор видит, можно ли безопасно поставить задачу на обновление |
| **Контроль установленной и подготовленной версии** | Нельзя повторно установить текущую версию или применить отсутствующий staged-пакет |
| **Проверка пакета до применения** | Повторная проверка SHA-256, Ed25519, ZIP-манифеста и предпосылок восстановления |
| **Подтверждение действий** | Обновление, backup и rollback выполняются только по разрешённому запросу администратора |
| **Журнал и уведомления** | События обновлений фиксируются и передаются в существующий механизм уведомлений |

## Быстрый старт

Для **локальной разработки из исходников** нужны PHP 8.4.1+, Composer 2, подходящий PDO-драйвер и расширения из `composer.json`.

```bash
composer install --no-interaction --prefer-dist
php bin/cajeer install --sqlite --interactive
php bin/cajeer doctor
```

Укажите web root `public/` в настройках веб-сервера. Административная панель после установки доступна по `/admin/`. Для локального изучения допускается SQLite; для поддерживаемого production-профиля основной вариант — PostgreSQL 17+ на одном Linux-узле.

> [!CAUTION]
> Не используйте ZIP исходников (`source.zip`) как готовый production-дистрибутив. На сервере устанавливают **проверенный подписанный `dist.zip`**; правила для доверенного ключа, резервных копий и обновления приведены в [инструкции](docs/releases/upgrade-2.1.0.md). Не передавайте реальные секреты в примерах команд или Git-репозиторий.

## Технологии и устройство

```text
admin/              Административные интерфейсы (Static SPA и Nuxt)
api/openapi.yaml     Контракт REST API
core/               Ядро CMS, модули, права, обновления и интеграции
bin/cajeer          CLI: установка, диагностика, миграции и управление
migrations/         SQL-миграции
public/             Публичная точка входа и опубликованные assets
templates/          Шаблоны .cjr
packages/           SDK и дополнительные пакеты
tools/              Проверки, сборка и релизный конвейер
docs/               Руководства по продукту и эксплуатации
```
